# ИИ: ACP, свой ключ и подписка

План, разобран 2026-10-22, код не начат. Пункт «ИИ в веб-версии: по ключу с
бэкенда» из [todo.md](todo.md). Правило, по которому он сделан, — из
[client-server-plan.md](client-server-plan.md): что нужно обеим сборкам,
делается в них одинаково. Когда шаг сделан, его текст переезжает в
[architecture.md](architecture.md), а отсюда уходит.

## Схема

Источников ИИ три:

- **ACP** — CLI агента на машине (claude, codex…), как сейчас;
- **свой ключ** (BYOK) — Go сам ходит в API модели по ключу человека;
- **подписка** — человек входит в наш аккаунт, и Go ходит в API модели через
  наш шлюз. В этом пункте — только шов: провайдер, у которого вместо ключа
  токен входа. Бэкенд и биллинг — отдельный пункт.

**В подписке есть одно — ИИ по нашему ключу.** Всё остальное есть без неё:
доски, шаблоны, темы, сервер, источники, CLI-агенты и свой ключ. Платного
издания больше нет ([deferred.md](deferred.md), «Платное издание»). Подписка
ограничивает только расход модели через наш шлюз; функцию за неё не прячут.

|                         | Десктоп (стендэлон)  | Облако (серверная сборка) |
|-------------------------|----------------------|---------------------------|
| ACP                     | да                   | нет                       |
| Свой ключ               | да                   | да                        |
| Подписка                | да                   | да                        |
| Папки                   | да, у любого из трёх | нет                       |
| MCP источников и агентов | stdio и HTTP        | только HTTP (streamable, SSE) |

**Всё, что делает ИИ**, кроме CLI, закрывают свой ключ и подписка: сессия по
карточке, планирование, сортировка «Входящих», источник через агента и то,
что появится потом. Новая функция ИИ пишется против исполнителя по API, а не
против ACP.

**Ключ и агенты — человека.** Командной работы пока нет: у доски один
владелец, он же пользователь. На десктопе человек — `SingleUser`, и «ключ
установки» — это его ключ. В облаке у каждого зарегистрированного свой ключ и
свои агенты. Сессию оплачивает ключ владельца агента — других людей на его
доске нет. Администраторы этому пункту не нужны.

«Исполнитель» — слово кода и этого плана. На экране по-прежнему **агент**,
а исполнитель — его вид: «CLI на этой машине», «Модель по ключу», «Модель по
подписке».

## Разбор: что завязано на ACP, CLI и папку

Прочитаны `internal/acp`, `internal/boardmcp`, `internal/boardadapter` и
`boardapi.go`. Большая часть сессии от исполнителя уже не зависит.

### Не зависит от исполнителя

- **Запуск по переносу** (`trigger.go`): `handleEvent`, `assignedAgent`,
  `movedByAgent`, `claimIdempotent`, `cancelForMove`, `aiSwitchedOff`.
- **Агент как аккаунт доски** (`EnsureAgentAccounts`, `AgentUsername`,
  `humanAssignee`, `agentAssignees.ts`).
- **Что агенту сказано** (`composePrompt`, `promptLead`, `boardStanding`,
  `cardInputs`, `resultBrief`).
- **Вопросы и внимание** (`question.go`, `attention.go`, `attentionack.go`):
  `ask`, `awaitAnswer`, `AnswerQuestion`, `Attention()`, ack. От ACP только
  **источники** вопросов: `RequestPermission` (`client.go`) и элицитация
  (`elicitation.go`).
- **Уведомления**: стопка, «Ждут» на телефоне, трей и ОС (`alerts.go`) читают
  `Manager.Attention()`.
- **Инструменты доски** (`boardmcp`, `boardtools.go`, `stagereport.go`):
  `finish_work`, `comment_card`, `update_card`, `move_card`, `create_cards`,
  выдача на прогон, `grantedCard`, `noteAgentMove`, `commentFirstTurn`. От ACP
  только **доставка**: объявление в `session/new` и HTTP на двери.
- **Простой и журнал**: `card_stall`, `agent_session`, события, `MaxConcurrent`,
  `SessionTimeout`. **Подпись записей** (`internal/author`, `asagent.go`).

### Только ACP и CLI

- `openConnection`, `agentLaunch`, `adapterArgv`, `connectACPAgent`,
  `selectSessionMode`, `selectSessionModel`, `applyAgentOptions`,
  `sessionMeta`, сам `conn.Prompt` в `runTurn`.
- `sessionClient`: поток чанков, разрешения, файлы с `jail`, терминалы.
- Прокси процесса (`spawnEnv`), трассировка провода (`tracepipe.go`), опрос
  возможностей через `session/new` (`capabilities.go`).

### Только с папкой

`resolveWorkdir`, `cardDrafts`, `WorkModeFor`, `folderIsFree`,
`ClaimWorkspace`, `prepareWorkdir`, `cleanupWorktree`, `FoldWorktree`,
`branchState`, изменения карточки (`carddiff.go`), ветка, выбор папки
в планировании, строки про ветку в `doneComment`/`failComment`.

### Что общее для любого исполнителя, но не для любой сборки

Политика инструментов (`policy.go`, `autoAllowTools`, `Bash(git *)`) — про
команды в папке. Исполнитель по API на десктопе получит те же команды, значит,
и ту же политику. В облаке команд нет, и политика не нужна.

### Вывод

Сессия делится по двум независимым осям: **как идёт ход** (ACP или API) и
**есть ли папка** — а это решает сборка, а не исполнитель.

## Как ввести исполнителя

### Агент остаётся записью реестра

Одна таблица `agent`, `kind` различает исполнителя:

- `claude`, `codex`, … — ACP, как сейчас;
- `api` — модель по ключу: `settings.provider` (`anthropic`, позже `openai`),
  `model`, `prompt`, `options` (для Anthropic — `effort`);
- `subscription` — модель по подписке: то же, провайдер — наш шлюз.

**Владелец агента** — новая колонка `agent.owner_id`, внешний ключ на
`users(id)`. На десктопе это `SingleUser`, существующие записи получают его в
миграции. Реестр, который видит человек, — его агенты; `assignedAgent` ищет
по аккаунту агента, как сейчас, и аккаунты по-прежнему уникальны. Схема
меняется в `tools/schemagen` с `go generate`.

### Шов в `internal/acp`

```go
// executor is how one session's turns are run.
type executor interface {
	Open(ctx context.Context, s *Session) (conversation, error)
}

type conversation interface {
	// Turn runs one prompt to the end; text deltas go to the chunk emitter,
	// questions go through Manager.ask.
	Turn(ctx context.Context, prompt string) (final string, err error)
	Close()
}
```

`acpExecutor` — нынешние `openConnection` и `runTurn` без изменений.
`apiExecutor` — новый, один для `api` и `subscription`. Папку готовит
`runSession`, как сейчас, если сборка с папками (`foldersAvailable` —
константа сборки, как `attachableBuild`); в облаке её нет ни у кого.

### Исполнитель по API

Новый пакет `internal/modelapi` не знает ни доски, ни ACP. В нём провайдер,
поток ответа, вызовы инструментов, отмена по контексту, расход токенов.
Anthropic подключается через официальный `github.com/anthropics/anthropic-sdk-go`,
потоком, с адаптивным мышлением и `effort` из `options`. Провайдер подписки —
тот же клиент с адресом шлюза и токеном входа вместо ключа. Цикл инструментов
пишем свой: нужны вопрос человеку посреди хода, отмена по переносу и счётчик
шагов.

**Инструменты модели собираются из трёх наборов:**

1. **Доска** — тот же сервер `boardmcp`, подключённый клиентом MCP в памяти
   (`mcp.NewInMemoryTransports`, go-sdk v1.6.1). Одна поверхность и одна
   проверка `grantedCard` для CLI и для модели. `main` отдаёт менеджеру тот
   же `open`, которым пользуется маршрут `/acp/board/mcp`.
2. **Папка** — только на десктопе, свой пакет `internal/foldertools`:
   `read_file`, `list_files`, `search`, `write_file`, `edit_file`,
   `run_command`. Пути — в пределах рабочей копии карточки (тот же `jail`, что
   у `sessionClient`). Команда вне политики — вопрос на карточке
   (`QuestionPermission` через `Manager.ask`), «разрешить всегда» помнится до
   конца сессии, как у CLI. Таймаут и вывод команды ограничены; процесс — в
   своей группе (`procgroup`), отмена её убивает.
3. **MCP-серверы агента** (`AgentEntry.MCPServers`) и источника: на десктопе —
   stdio и HTTP, в облаке — только HTTP (streamable или SSE: в go-sdk есть оба
   клиента). stdio-сервер в облаке — ошибка при сохранении агента или
   источника, а не при запуске.

**Вопрос человеку словами — инструмент `ask_person`** (текст, варианты, можно
ли ответить своими словами), тоже через `Manager.ask`. Дальше путь
существующий: бейдж, стопка, «Ждут», первый ответ выигрывает.

**Конец стадии** — как у CLI: `finish_work`, или `commentFirstTurn` пишет за
агента. Предел шагов цикла (`maxToolRounds`) — защита от хождения по кругу.
Отказ модели (`stop_reason: refusal`) — стадия не сделана, причина в
комментарии; серверный `fallbacks` у Anthropic включён.

**Кэш промпта**: система и список инструментов неизменны в пределах сессии и
стоят первыми, `cache_control` на конце системы. Расход (`usage`) пишется
событием сессии.

### Облако: без папки

- `startSession` не ищет папку и не делает черновики; в `composePrompt` вместо
  строки о рабочей копии — «файлов у тебя нет, результат — текст на карточке».
- На странице нет поля «Папка», папок в ⋯ доски, изменений карточки, выбора
  папки в планировании, вида агента «CLI».
- Сессия, комментарий, перенос, вопросы, планирование, сортировка — те же.

### Подключённый десктоп

Десктоп, подключённый к серверу (`attach.go`), продолжает работать карточки
сервера своими агентами — ACP, по ключу или по подписке, с папками. Ловушка:
`assignedAgent` ищет агента по id, потом **по имени**, и одноимённого агента
на сервере и на десктопе запустят оба. Для чужой доски (`BoardSource` не
свой) поиск только по id — правка в шаге 6 с тестом.

## Ключ, провайдеры, модели, настройки

### Где ключ

В `secrets.Store` (`openVault`), под именем **человека**:
`ai/<userID>/anthropic`. На десктопе это связка ключей ОС и `SingleUser`; в
облаке — файл с правами 0600 (что это не конечное состояние, уже сказано в
`internal/secrets`). Переменная окружения `PP_…` читается как
сейчас — это удобно для десктопа в разработке; в облаке ключи людей в
окружении не живут.

Страница ключ не видит никогда. Привязки, все от имени вошедшего:

- `AIProviders()` — по провайдеру: `keySet`, откуда ключ (`env`/`store`);
  у подписки — вошёл ли человек;
- `SetAIProviderKey(ctx, provider, key)` — перед сохранением проверяет ключ
  списком моделей, отказ — кодом `apperr`; `ClearAIProviderKey`;
- `AIModels(ctx, provider)` — модели у провайдера по ключу, кэш на время
  работы. Модели не зашиты: провайдер сам говорит, что у него есть.
  Подсказка по умолчанию для Anthropic — `claude-opus-5-5`.

Вход в подписку — шов: `SignInSubscription`/`SignOutSubscription`, токен в
том же хранилище под `ai/<userID>/subscription`. Без бэкенда провайдер
подписки отвечает «недоступно», и вид агента не предлагается.

### Провайдеры

1. **Anthropic** — первым.
2. **OpenAI** — вторым, официальным `openai-go`, тот же `modelapi.Provider`.
3. **Подписка** — когда будет шлюз.
4. **Совместимый с OpenAI по адресу** (OpenRouter, локальная модель) — когда
   попросят.

### Настройки на экране

- **«Настройки» → панель «ИИ»**: переключатель `aiEnabled` переезжает сюда из
  `appPanel.tsx`; под ним провайдеры — поле ключа, «задан / не задан»,
  «Убрать»; вход в подписку, когда он будет. Это настройки человека — их
  меняет он сам.
- **Агенты** — в той же панели «ИИ», одна форма «Подключить агента…»: вид
  «Программа на этом компьютере» (только десктоп) или «Модель по ключу API»,
  потом — «Модель по подписке». Для модели — провайдер, ключ прямо в форме
  (один на провайдера), модель из `AIModels`. У доски экрана агентов нет.

### `aiEnabled`

Один переключатель на всех исполнителей: `SetSwitchedOff` уже стоит на входе
в `handleEvent`, `startSession`, `StartPlanning`, `RunInbox`, и `apiExecutor`
идёт через них. Ключ не задан — это не выключатель, а причина простоя
`ai.no-key` на карточке.

## Чего не будет в этом пункте

- Бэкенд подписки, вход, биллинг, лимиты — только шов.
- Совместная работа: у доски один владелец ([deferred.md](deferred.md),
  «Совместная работа над доской»).
- Postgres и MySQL: таблицы агентов на них выключены (`appTablesSupported`),
  значит, и ИИ. Облако с ИИ — на SQLite, пока не сделан пункт про диалекты
  в `deferred.md`.

команда с вопросом; разбор «Входящих» моделью.

- нескольких ключей одного провайдера (OpenAI и OpenRouter сразу) — один ключ и
  один адрес на провайдера;
- ограничения расхода, кроме `maxToolRounds`, `MaxConcurrent` и таймаута; расход
  пишется событием сессии (`usage`) и нигде не показывается.

## Решить потом

- **Две таблицы вместо одной `agent`**: `ai_api` (модель по ключу) и
  `acp_agent` (CLI), обе привязаны к пользователям. Сейчас это одна таблица с
  `kind` и `owner_id`, и у модели пустуют поля процесса, а у CLI — провайдер.
- **В облаке всё решает подписка**, а не эти таблицы: какие модели и сколько,
  кто платит. Таблицы ключей и агентов там — то, что человек принёс сам, если
  подписка это разрешает.
- **Общий слой для трёх проектов** — [shared-ai-layer.md](shared-ai-layer.md).
