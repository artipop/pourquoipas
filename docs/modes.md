# Режимы: что где работает

Справочник, сверен с кодом 2026-10-22. Режимов четыре, а сборки две: десктоп
(Wails, окно) и сервер (`-tags server`, страница в браузере). Правило одно для
всего ниже: **что нужно обеим сборкам, делается в них одинаково**
([client-server-plan.md](client-server-plan.md)); расходятся они транспортом,
тем, кто вошёл, и тем, есть ли под ними машина человека.

| | Где | Кто пользуется |
|---|---|---|
| **Компьютер** (стендэлон) | десктоп | один человек, без входа (`SingleUser`) |
| **Компьютер, подключённый к серверу** | десктоп + сервер | человек входит на сервер; агенты остаются на компьютере |
| **Сервер в браузере** (веб) | серверная сборка | много людей, у каждого свой вход и свои доски |
| **Телефон** | окно на `https://<сервер>/m` | вход на сервер; до компьютера телефону не дотянуться |

## Люди и доски

- **У доски один владелец, он же её пользователь.** Совместной работы над
  доской нет и сейчас не делается ([deferred.md](deferred.md), «Совместная
  работа над доской»); что было придумано про команды и общий пул задач — в
  `../xxvi/docs/teamwork.md`, под вопросом.
- **Команды Focalboard** убираются: на установке одна команда `0`, шаг 4
  [client-server-plan.md](client-server-plan.md).
- **Вход** — только на сервере. Первый зарегистрировавшийся — администратор,
  дальше регистрация по ссылке-приглашению («Настройки → Люди», видит только
  администратор). На компьютере никого не спрашивают
  ([teamwork.md](teamwork.md)).
- **От командного режима в коде остались** адресат ожидания агента и
  «Поделиться» с участниками — они работают на сервере (`teamMode`), но не
  развиваются. Комментарии на карточке показываются везде: это итог работы
  агента.

## ИИ

| | Компьютер | Подключённый | Сервер в браузере |
|---|---|---|---|
| CLI-агент по ACP | да | да, на компьютере | нет |
| Модель по своему ключу (BYOK) | да | да, на компьютере | да, на сервере |
| Подписка: ИИ по нашему ключу, и только он | не сделана, только в плане | — | — |
| Папки, ветки, рабочие копии, изменения карточки, черновики | да, у любого агента | да | нет |
| Файлы и команды у модели | да, в копии карточки | да | нет: работа модели — то, что она пишет на карточке |
| MCP-серверы агента | stdio и по адресу | stdio и по адресу | только по адресу; процесс запускается, только если это само приложение |
| Прокси агента | да | да | нет |
| Планирование («Обсудить с агентом») | да | да | да, без папки |
| Разбор «Входящих» агентом | да | да | да |

- **Агент** — запись реестра: `claude`, `codex`, … (CLI по ACP) или `model`
  (провайдер и модель). Назначается на карточку полем «Кто занимается»,
  одинаково для обоих видов ([architecture.md](architecture.md), «A stage has
  two executors…»).
- **Ключи и агенты — человека.** Ключ хранится в связке ключей (на сервере — в
  файле с правами только для приложения) под человеком, страница видит «задан» и
  хвост ключа. Агент-модель работает на ключе своего владельца
  (`agent.owner_id`; на компьютере пусто — всё одного человека). Первый ключ
  провайдера сам заводит агента-модель.
- **Где настраивается.** «Настройки → ИИ»: переключатель агентов, ключи
  провайдеров (Anthropic, OpenAI и совместимые по адресу), список агентов
  обоих видов. Тот же список — в ⋯ доски → «Агенты…», там же прокси.
- **Переключатель «Агенты работают с карточками»** (`aiEnabled`) — один на всех
  агентов. На компьютере его меняет человек за ним, на сервере — администратор
  (`ownsTheInstall`).
- **Подключённый компьютер** работает карточки сервера своими агентами: своими
  CLI, своими ключами, в своих папках. Пишет на сервер под учётками агентов.
- Что осталось сделать — [web-ai-plan.md](web-ai-plan.md).

## Вопросы агента и уведомления

| | Компьютер | Сервер в браузере | Телефон |
|---|---|---|---|
| Бейдж и вопрос на карточке | да | да | — |
| Стопка уведомлений в окне | да | да | — |
| Уведомления ОС, значок у часов | да | нет | — |
| Экран «Ждут» | — | — | да |

Ответ из любого места снимает вопрос везде (`AnswerQuestion`, ack у Go).

## «Входящие» и источники

- **«Входящие»** — одна доска на установку. На сервере она открытая и одна на
  всех вошедших, что расходится с «у доски один владелец» ([todo.md](todo.md)).
- **Источники-плагины и MCP-манифесты** работают в обеих сборках, но только на
  SQLite (`appTablesSupported`). На сервере процесс источника запускается на
  сервере — правило «никаких процессов на выбор человека» на источники пока не
  распространено ([todo.md](todo.md)).
- **«Поделиться» из системы** (share sheet) — только компьютер (macOS).
- **Приём по токену** (`/sources/ingest`) — обе сборки.

## Настройки

- **Человека** — тема, язык, последняя доска и вид: `preferences`, через
  `/users/me/config`. В обеих сборках, у каждого своё.
- **Установки** — `aiEnabled`, `agentNotifications`, `prefillCardFolder`:
  `system_settings`.
- **Ключи моделей и агенты** — человека (выше).
- **Обновления приложения** — только компьютер («Настройки → Обновления»).
- **Подключение к серверу** — только компьютер («Настройки → Сервер»).

## Транспорт

- **Компьютер:** страница на `wails://`, REST в процессе, изменения доски и
  события агентов — шиной Wails. В шину идут только сообщения для человека за
  компьютером (`emitForUser`).
- **Подключённый:** REST и `/ws` сервера через Go (`sockettunnel.go`).
- **Сервер:** Wails server mode, вход, сессии, `/ws`, база по выбору
  (`PP_DB_TYPE`, `PP_DB_DSN`); на Postgres и MySQL нет агентов и источников.
- **Телефон:** окно на `/m`; данные — привязки сервера и сокет событий.

## Чего нет ни в одном режиме

- деплоя: Dokku ушёл в Gandvík шаблоном стадии ([deferred.md](deferred.md));
- tailnet-двери: телефон к компьютеру не подключается;
- подписки и общего бэкенда;
- платного: сборка одна, и всё, кроме ИИ по нашему ключу, бесплатно.
