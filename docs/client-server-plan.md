# Стендэлон и сервер: куда идём

План, принят 2026-10-21. Здесь описано, как приложение устроено сейчас, к какой
схеме мы идём и в каком порядке. Когда шаг сделан, его текст переезжает в
[architecture.md](architecture.md), а отсюда уходит.

## Как устроено сейчас

**Десктоп сам по себе.** Окно Wails смотрит на front door (`frontdoor.go`): наш
HTTP-сервер на `127.0.0.1`, порт случайный на каждый запуск. `/wails/` дверь
отдаёт рантайму Wails, остальное проксирует на сервер доски — форк Focalboard в
том же процессе, на своём петлевом порту (`proxy.go`). Страница — клиент
Focalboard: читает и пишет доску через REST (`/api/v0`), изменения получает по
сокету `/ws`. С Go она говорит привязками (HTTP-транспорт Wails через ту же
дверь), события агентов слушает на `/acp/events/ws`.

Дверь нужна потому, что страница в вебвью загружена не по сети, и сокет ей
открыть некуда: asset server Wails отвечает на upgrade 501. `/ws` при этом нужен
и одному человеку — доску меняет не только он, но и агенты со стороны Go.

Через ту же дверь ходят и другие процессы: MCP-инструменты агентов
(`/acp/board/mcp`, токен выдачи), скрипты и вебхуки (`/sources/ingest`, токен
источника), лента колонки (свой токен).

**Десктоп, подключённый к серверу** ([teamwork.md](teamwork.md)). Та же дверь,
но прокси смотрит на сервер: страница своя, данные (`/api/v0`, `/ws`) — с
сервера. Агенты остаются на десктопе и пишут на сервер клиентом доски на Go.

**Сервер** — та же программа с тегом `server`. Своей двери у неё нет: сервер
Wails и есть дверь, наши маршруты — его middleware (`mode_server.go`). Вход по
паролю, сессии, `/ws`, база по выбору (SQLite, Postgres, MySQL; агенты и
источники — только на SQLite).

**Телефон** (`mobile/`) — окно на `https://<сервер>/m`. До десктопа ему не
дотянуться: tailnet-дверь убрана ([deferred.md](deferred.md)).

**Команды.** Схема и API Focalboard командные (`team_id` у досок, маршруты
`/teams/{teamID}/…`), но команда на установке одна, `0`. Так было и у
Focalboard: настоящие команды жили только в плагине Mattermost, а отдельный
сервер отдавал все команды без проверки участия.

## Куда идём

Два режима и никаких команд.

### Стендэлон: один человек, одна машина

- Страница грузится из самого Wails (`wails://`), а не с нашего порта.
- REST идёт через `AssetOptions.Handler` прямо в доску внутри процесса, без
  сети. Сам Wails так уже отправляет вызовы привязок, значит тела запросов
  проходят — но см. «Открытые вопросы».
- Изменения доски приходят событиями Wails вместо `/ws`. Человек один, подписки
  и фильтр по пользователю не нужны; событие достаёт до всех окон приложения
  (доска, изменения карточки, «Поделиться»). Сокет событий агентов уходит тоже:
  эти события уже идут в шину.
- Локальный порт остаётся, но только для других процессов: MCP агентов,
  `/sources/ingest`, лента колонки. Каждый маршрут — со своим токеном. Страницу
  он не отдаёт, поэтому проверки `Host`/`Origin` и сам front door уходят. С
  безопасностью становится лучше: сейчас любой, кто запросит страницу с этого
  порта, получает токен сессии доски.
- Телефон в этом режиме — через Apple CloudKit (кандидат; что уже разобрано —
  [icloud-sync.md](icloud-sync.md)).

### Приложение + бэкенд: развёрнутый сервер, много пользователей

- Сервер — как сейчас: Wails server mode, вход, сессии, `/ws`, база. Людей
  много, но у каждого свои доски: совместной работы над доской нет
  ([deferred.md](deferred.md), «Совместная работа над доской»).
- Десктоп — клиент. Страница так же `wails://`; Go проксирует REST на сервер,
  сам держит соединение с его `/ws` и передаёт изменения странице событиями
  Wails. Для страницы оба режима выглядят одинаково: REST на свой origin,
  изменения из шины.
- Агенты с папками и CLI остаются на десктопе и пишут на сервер под аккаунтом
  агента, как сейчас. На самом сервере работают агенты по ключу и по подписке,
  без папок ([web-ai-plan.md](web-ai-plan.md)).
- Браузер и телефон ходят в API сервера напрямую, изменения получают по `/ws`.

### Команды

Убираем. Один сервер — много людей, у каждого свои доски; вход, доступ к
доскам (`board_members`) и публичные ссылки остаются. Понадобятся команды —
сделаем заново и по-настоящему, раз в Focalboard их так и не сделали.

## Как разделить стендэлон и API-режим

**Правило: что нужно обеим сборкам, делается в них одинаково.** Стендэлон и
веб-версия расходятся транспортом (шина или сокет, провод в памяти или HTTP) и
тем, кто вошёл (один человек или логин), — и больше ничем. Настройки, ИИ,
шаблоны, переключатели живут в одном месте и работают одним кодом; отдельный
путь только для одной сборки нужен, когда другой он невозможен (папка и CLI
агента — только на машине), и это записывается рядом.


Слои сейчас такие: сервис доски (`server/app`) — одна реализация на оба режима;
поверх него REST Focalboard (`server/api`, с входом и правами) и рассылка
изменений (`ws.Adapter`); наши функции — привязки `App`. Агенты пишут в доску
через сервис напрямую (`boardadapter`), без REST.

- **Принятый вариант — менять транспорт, а не API.** Стендэлон: REST идёт в
  процессе (asset handler → роутер доски по проводу в памяти), рассылка — в
  шину Wails (`SetSink`). Сервер: тот же REST по HTTP и `/ws`. Код сервиса и
  страницы один, разница — в паре строк в `main.go` и `busSocket.ts`.
- **Отклонено пока — доска через привязки.** Server mode Wails отдаёт те же
  привязки по HTTP, и привязка видит контекст запроса (`r.Context()`), так что
  пользователя туда положить можно. Но `/wails/events` рассылает всем подряд,
  без входа и без деления по пользователям, а REST Focalboard уже умеет и то, и
  другое. Переписывать `octoClient.ts` на привязки — большая работа без выигрыша
  для пользователя.
- **gorilla/websocket** остаётся, пока сервер отдаёт `/ws` и `/acp/events/ws`
  браузеру; на десктопе она нужна только туннелю к подключённому серверу.
  Можно свести к одной библиотеке — `coder/websocket`, которую тянет Wails.

## Шаги

1. ~~**Стендэлон на `wails://`.**~~ Сделано 2026-10-21, описано в
   [architecture.md](architecture.md), «The front door owns the origin».
   Изменения доски и события агентов идут шиной Wails (`ws.Server.SetSink`,
   `BusFeed`); туннелем сокетов через Go (`sockettunnel.go`) ходит только `/ws`
   подключённого сервера. Проверено на macOS:
   доска грузится, карточка, созданная снаружи, появляется без перезагрузки,
   события агентов доходят, вложение на 3 МБ загружается кнопкой «Прикрепить»,
   `wails3 dev` с горячей подменой работает. На Windows не проверялось.
2. ~~**Петлевой порт только для процессов.**~~ Сделано 2026-10-21: дверь
   отдаёт только MCP агентов, ленту и ingest; у сервера доски порта нет
   совсем (`boardwire.go`); события агентов на десктопе идут шиной.
3. **Клиентский режим на той же схеме.** Go проксирует REST на сервер и
   пересылает его `/ws` в шину. Заодно снимается, что переключение доски
   перезагружает страницу.
4. **Команды.** Сначала всё прибить к `0` и убрать то, что предлагает выбрать
   команду: переключатель, `GET /teams` в смысле «список», приглашение в
   команду. Потом вычистить `team_id` из схемы и маршрутов — отдельным
   изменением, со строкой в `docs/fork-shrink-removed.md`.
5. **Телефон** — после 3: клиент API сервера под своим логином. CloudKit для
   стендэлона — отдельным разбором.

## Открытые вопросы

- **Большие тела запросов на Windows.** WebView2 доставляет тело запроса к
  своему обработчику только до ~2 МБ; Wails режет на части свои вызовы
  привязок, а загрузку вложений в `/api/v0/files` — нет. На macOS 3 МБ
  проходят (после `sendableForm`), Windows не проверялся. Если упрётся — вести
  загрузку файлов привязкой.
- **Ссылка на карточку.** «Скопировать ссылку» берёт адрес страницы: раньше
  это был `http://127.0.0.1:<порт>`, менявшийся при каждом запуске, теперь
  `wails://localhost/…`. Снаружи не открывается ни то, ни другое; нужна своя
  схема (`pourquoipas://` уже зарегистрирована для расширения «Поделиться»).
- ~~**Изменения доски — событиями Wails.**~~ Сделано 2026-10-22: хаб доски
  отдаёт каждую рассылку ещё и в шину (`ws.Server.SetSink`), страница на
  десктопе слушает её без сокета. Туннель остался для подключённого сервера.
- **REST доски напрямую.** В стендэлоне REST идёт через
  `httputil.ReverseProxy` по проводу в памяти; asset handler мог бы звать
  роутер доски сам, без прокси.
- **Таблицы приложения в клиентском режиме.** Наши таблицы ссылаются на
  `blocks(id)` внешним ключом, а в клиентском режиме блоки на сервере. Как
  сейчас живут `agent_session` и прочие для карточки сервера — проверить и
  записать до шага 3.
- **Уведомления на телефон**, когда приложение закрыто, требуют пуша с сервера;
  в стендэлоне без сервера — только CloudKit-подписки.
