# Сборка: что её тормозит и что можно убрать

План, а не описание: когда пункт сделан, он переезжает в описание
(`build-and-platforms.md`, `webapp.md`) или вычёркивается отсюда.

## Замеры

2026-09-15, macOS arm64, одна машина, по одному прогону.

| Что | Время |
|---|---|
| `npm run pack` (Vite, production) | 9 с, из них сборка 8 с |
| `vitest run` без покрытия | 46 с настенных, 180 с CPU; jsdom-окружение 77 с CPU, импорт 41 с |
| `go build` десктопа, пустой `GOCACHE` | 62 с настенных, 206 с CPU |
| `wails3 task darwin:build`, фронт не менялся | 67 с — кеш холодный, см. ниже |
| `go build` повторно, без изменений | меньше секунды |
| `go test -run '^$' ./...`, только компиляция | 21 с при тёплом кеше |
| бинарь | 83 МБ, 777 пакетов, 860 модулей в графе |
| `webapp/node_modules` | 337 МБ, 561 пакет |
| `webapp/pack` | 18 МБ, главный чанк 2,46 МБ (684 КБ gzip) |

**Вывод, который надо сказать первым: фронт — не узкое место сборки.** Vite
укладывается в 9 секунд. Долгое — это Go, и почти всегда из-за холодного кеша.
Фронт стоит времени в другом месте: 46 секунд тестов, `npm ci` и 2,4 МБ
главного чанка, который вебвью парсит при каждом старте.

## Go

### Куда уходит компиляция

CPU по модулям при пустом кеше (`go build -debug-actiongraph`), всего 173 с:

| Модуль | с | |
|---|---|---|
| `tailscale.com` + `gvisor` + wireguard | ~75 | 43 %, всё ради `tsnetdoor.go` |
| стандартная библиотека | 31 | |
| прочие сторонние | 19 | |
| `modernc.org/sqlite` + `libc` | 18 | в cgo-сборке не используется |
| линковка | 8 | на каждое изменение корневого пакета |
| `golang.org/x/*` | 6 | |
| наш код (`internal`, `server`, корень) | 7,5 | |

### 1. Три набора флагов — три кеша

Дев-сборка идёт с `-gcflags=all="-l"` (`build/darwin/Taskfile.yml`,
`build/Taskfile.yml`), релизная — с `-trimpath` и тегом `production`, тесты — без
того и другого. И `-gcflags=all`, и `-trimpath` входят в ключ кеша **каждого**
пакета, так что после `wails3 dev` сборка `wails3 task build` компилирует
tailscale и стандартную библиотеку заново, а `go test` — третий раз. Это и есть
67 секунд «на ровном месте».

Что сделать: убрать `-gcflags=all="-l"` из дев-сборки (он нужен только отладчику,
а отлаживают здесь логами) или сузить до `-gcflags="-l"` для своего пакета, и
проверить, насколько после этого совпадают кеши дев- и релизной сборки: тег
`production` меняет только пакеты с файлами под ним. **Сначала замерить** —
пересборку после `wails3 dev` до и после. Риск нулевой, выигрыш — самый большой
в этом списке.

### 2. modernc.org/sqlite в cgo-сборке

Его тянет `golang-migrate/.../database/sqlite` из `sqlstore/migrate.go`, а в
сборке с cgo базу открывает mattn. Развести импорт драйвера миграций по тем же
тегам, что и сам драйвер (`sqlite.go` / `sqlite_pure.go`): под `sqlite3 && cgo`
— `database/sqlite3` (mattn), иначе — `database/sqlite`. Минус 18 с CPU на
холодной сборке и часть бинаря. Проверить: `go test -tags "json1 sqlite3"` и
без тегов для `sqlstore`, `wails3 task test:db DB=sqlite3`, сборку Windows.
`build-and-platforms.md` утверждает, что modernc «и так был в каждой сборке», —
после правки это надо переписать.

### 3. viper → `encoding/json`

Используется в одном файле, `server/services/config/config.go`: прочитать
`config.json`, дефолты, `AutomaticEnv` с префиксом `focalboard`. За собой тащит
hcl, toml, ini, afero, cast, fsnotify, mapstructure — около 25 пакетов. Замена —
структура с дефолтами, `json.Unmarshal` и явный проход по env для тех ключей,
которые реально задаются снаружи (сначала найти, какие: тесты и
`FOCALBOARD_STORE_TEST_*` к этому не относятся).

### 4. testify в релизном бинаре

`server/utils/testUtils.go` импортирует `testify/mock` из не-тестового файла, и
testify попадает в сборку. Перенести в пакет, который импортируют только тесты.
Мелочь по времени, но это просто неправильно.

### Чего не делать

- **Выпиливать tailscale.** Это дверь наружу, и других нет. Если после пункта 1
  холодные сборки всё ещё мешают, можно подумать о теге, который отключает
  `tsnetdoor.go` в дев-сборке, но тогда дев-сборка перестаёт проверять эту дверь.
- **Убирать mysql/pq из десктопа.** Выигрыш около секунды, а `test:db` и
  серверная сборка ими пользуются.
- `golang/mock` архивирован и просится на `go.uber.org/mock`, но на скорость это
  не влияет — отдельная задача.

## Фронт

### 1. Лишние зависимости — удалить сразу

- `color` и `@types/color` — не импортируются нигде;
- `fullcalendar` — мета-пакет, код импортирует только `@fullcalendar/*`;
- `isomorphic-fetch` — 15 тестов импортируют его, а в Node 24 `fetch` есть;
- `cypress` записан дважды, в `devDependencies` и `optionalDependencies`, и при
  каждом `npm ci` качает свой бинарь; CI (`test.yml`) cypress не запускает —
  `CYPRESS_INSTALL_BINARY=0` в окружении шага;
- `prettier` 2 — только для `fix:scss`, рядом есть `stylelint --fix`. Удалить,
  если скрипт никто не зовёт.

### 2. Мёртвые файлы в `pack` — и в бинаре

`appStatic` копирует `webapp/static/` целиком, а в нём лежит то, на что код не
ссылается: `emoji_spirit.png` (3,7 МБ — комментарий в `emojiPicker.tsx` уверен,
что он больше не поставляется), `boards-screenshots.png`, `boards-welcome*.png`,
`onboardingBg.jpg`, `upgrade.png`, `app-bar-icon.png`. Гифки тура импортируются
из TS, Vite кладёт их с хешем, а `appStatic` копирует ещё раз без хеша — около
4 МБ дублей. Удалить неиспользуемые, а импортированные вынести из `static/`.
Перед удалением проверить шаблоны сервера и письма — сейчас ссылок нет.

### 3. Главный чанк: что сделать ленивым

По исходникам в source map главного чанка (4 МБ до минификации, половина — наш
`src`):

- **FullCalendar** — 525 КБ исходников, а импортируется напрямую из
  `centerPanel.tsx` и превью шаблона. Календарный вид — `lazy()`.
- **Холст маршрутов** — `@dschz/solid-flow`, `@xyflow/system`, d3 — около
  330 КБ; `AutomationDialog` импортируется из меню вида напрямую. Диалог —
  `lazy()`.
- **emoji-mart** — `main.tsx` делает `init` с `@emoji-mart/data` (424 КБ JSON)
  до первой отрисовки. Инициализировать при первом открытии пикера или первом
  `:` в редакторе.

`xterm`, Lexical, мобильные экраны и «Поделиться» уже ленивые.

### 4. Мелкие библиотеки заменить своим кодом

- `lodash` — 113 КБ ради пяти функций: `debounce` (4 файла), `difference` (2),
  `cloneDeep`, `isEqual`, `throttle`. `cloneDeep` — `structuredClone`,
  остальное — десяток строк в `utils`.
- `classnames` — один файл.

### 5. moment → `Intl` — большая отдельная работа

153 КБ в главном чанке и 293 КБ чанка локалей. Используется в пяти файлах:
свойство «дата», фильтр дат, расчёты, `utils.ts`, `dateUtils.ts`, плюс
`hooks/momentLocale.ts` для «2 часа назад» (`docs/i18n.md`). Замена —
`Intl.DateTimeFormat` и `Intl.RelativeTimeFormat`, но форматы дат приходят из
данных досок Focalboard, и их надо разобрать до кода. Не делать вместе с
остальным.

### 6. Тесты: 46 секунд

Время съедает окружение, а не сами тесты: jsdom 77 с CPU, импорт 41 с, тесты
28 с. Варианты, каждый — сначала замер:

- покрытие включено по умолчанию (`enabled: true`), то есть обычный `npm test`
  платит за v8-счётчики; сделать `test:coverage` отдельным скриптом, а CI уже
  зовёт с `--coverage.enabled=false`;
- тестам без DOM (`store`, `blocks`, чистые модули) — `environment: 'node'`
  через проекты vitest; jsdom на файл — самая дорогая часть;
- `maxWorkers: '50%'` — проверить 75 %.

## Порядок

1. Флаги дев-сборки (Go, пункт 1) — замерить и поправить.
2. Дешёвое и безопасное: лишние npm-пакеты, мёртвые файлы в `static/`,
   `CYPRESS_INSTALL_BINARY=0`, testify из бинаря, покрытие не по умолчанию.
3. modernc из cgo-сборки.
4. Ленивые чанки: календарь, холст маршрутов, emoji-mart.
5. viper → json; lodash и classnames.
6. moment → `Intl` — отдельной задачей со своим разбором.
