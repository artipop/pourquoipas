# Сайт: лендинг и руководство

Лендинг и руководство пользователя — один сайт на Astro в `site/`. Лендинг —
страница Astro в корне (`site/src/pages/index.astro`), руководство под `/docs/`
рисует Starlight. Тексты руководства лежат не в `site/`, а в `docs/guide/`:
правило «фича не закончена, пока `docs/guide/` не рассказал как» осталось тем
же. Starlight читает их оттуда (`site/src/content.config.ts`), а остальное
содержимое `docs/` — записки для тех, кто пишет код, — на сайт не попадает.

## Почему Astro и Starlight

До этого было два проекта: лендинг на голом Vite и руководство на VitePress.
Два дев-сервера с прокси между ними, два набора шрифтов и две копии палитры.
Теперь проект один:

- **одна команда и один сервер.** `npm run dev` открывает и лендинг, и
  руководство, ссылка «Руководство» в шапке лендинга работает без прокси;
- **одна палитра и одни шрифты.** Шрифты приходят пакетами `@fontsource`,
  `site/src/styles/fonts.css` подключается и лендингом, и Starlight;
- **Starlight — сайт документации из коробки**: боковое меню, оглавление
  страницы, поиск (Pagefind, индекс собирается вместе со страницами, внешнего
  сервиса нет), два языка с переключателем и подсветка кода на сборке.

## Команды

```
cd site
npm ci
npm run dev      # http://localhost:4321/ — лендинг, руководство на /docs/
npm run build    # всё в site/dist
npm run preview  # посмотреть собранное
```

В деве поиск не работает: индекс Pagefind строится только при `build`.

## Адреса

- `/` — лендинг;
- `/docs/…` — руководство по-русски, `/en/docs/…` — по-английски.

Английский живёт под `/en/docs/`, а не под `/docs/en/`, потому что Starlight
берёт язык из первого сегмента адреса. Зато `/en/` свободен для английского
лендинга, если он появится.

Адреса — каталоги (`/docs/board/`, внутри `index.html`). GitHub Pages, Netlify,
Cloudflare и nginx отдают такой адрес сами.

Сайт может жить не в корне домена: GitHub Pages публикует проект под
`/<репозиторий>/`. Путь задаёт переменная `BASE_PATH` (по умолчанию `/`), её
передаёт workflow. Поэтому в разметке лендинга адреса пишутся через
`import.meta.env.BASE_URL`, а не начинаются с `/`.

## Публикация

`.github/workflows/pages.yml` собирает `site/` на каждый пуш в `main`, который
затрагивает `site/` или `docs/guide/`, и выкладывает на GitHub Pages. Путь и
домен берутся из `actions/configure-pages`. Один раз в настройках репозитория
нужно выбрать источник Pages «GitHub Actions».

Workflow делает checkout со всей историей: Starlight пишет на каждой странице
дату последнего изменения и берёт её из git.

## Как добавить страницу

1. Положить `.md` в нужный раздел `docs/guide/` (`automation/`, `inbox/`,
   `settings/` — или рядом с `board.md`, если раздел из одной страницы).
   Заголовок страницы — поле `title:` во frontmatter; Starlight рисует его как
   `#`, поэтому второго `#` в тексте не нужно.
2. Положить перевод в тот же путь под `en/`.
3. **Дописать строку в `sidebar` в `site/astro.config.mjs`.** Одна строка на
   оба языка: путь русской страницы, подпись по-русски и по-английски. Без неё
   страница собирается и открывается по адресу, но в меню её нет.

Ссылки между страницами — относительные, с расширением `.md`
(`../inbox/index.md`), как их читает GitHub. В адреса их переводит
`site/src/guide/links.mjs`; ссылка на несуществующий файл роняет сборку — это
и есть проверка ссылок. Ссылки на `docs/*.md`, записки для разработчиков, —
абсолютные, на GitHub: они не часть сайта.

Ссылки в frontmatter (кнопки на главной руководства) этот плагин не видит, они
пишутся относительно страницы: `board/`, а не `/docs/board/`.

## Два языка

Русский — оригинал, английский — перевод, страница в страницу: `en/` повторяет
дерево целиком, поэтому переключатель языка всегда ведёт на ту же страницу.

Подписи экрана в английских страницах — **не перевод на глаз, а строки из
`frontend/i18n/en.json`**: руководство, назвавшее кнопку иначе, отправит
читателя искать то, чего нет. Глоссарий для новой страницы проще всего собрать
так: вытащить из русской версии все `«…»`, найти их в `ru.json` и напечатать
рядом `en.json`.

Имена, которые приложение **даёт само** (доска «Входящие», колонка «Мои
задачи»), переводятся, как и остальной экран: английская страница называет их
Inbox и My tasks.

## Дизайн

Оформление — приложения (`frontend/src/styles/_tokens.scss`): кремовая бумага
и тёмно-синий корпус с иконки, горчичный только для того, что просит внимания,
морской для ссылок. Fira Sans Condensed капителью — то, что называет система,
Inter — текст, Playfair Display курсивом — только имена, JetBrains Mono — данные.

- `site/src/styles/site.css` — лендинг. Цвета объявлены только в двух блоках
  тем в начале файла.
- `site/src/styles/guide.css` — те же значения в словаре Starlight: его тёмная
  тема — корпус, светлая — бумага.
- `site/src/guide/SiteTitle.astro` заменяет заголовок Starlight: имя продукта
  ведёт на лендинг, слово «Руководство» — на начало руководства.

Лендинг и руководство помнят тему в одном ключе `localStorage`
(`starlight-theme`), так что переход между ними её не меняет.
