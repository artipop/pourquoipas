# Подключение агентов

Агенты подключаются в одном месте — **«Настройки» → «ИИ»** — и принадлежат
вам, а не доске. Любого своего агента можно назначить исполнителем карточки на
любой доске: он есть в поле исполнителя («Кто занимается», «Исполнитель» и т. п.)
рядом с людьми. Добавлять агента на доску не нужно.

Агент бывает двух видов:

- **«Программа на этом компьютере»** — Claude Code, Codex, GitHub Copilot,
  JetBrains Junie, Antigravity или другой агент по ACP. Приложение запускает
  программу, она работает под вашей учётной записью у своего провайдера и в папке
  карточки. Есть только на компьютере.
- **«Модель по ключу API»** — модель Anthropic, OpenAI или любого сервиса с API
  как у OpenAI. Приложение обращается к ней само, на вашем ключе. Ставить ничего
  не нужно. Есть и на компьютере, и на сервере.

Назначают, запускают и спрашивают обоих одинаково: вопросы, комментарий, перенос
карточки и уведомления у них общие.

## Раздел «ИИ»

Сверху — переключатель **«Агенты работают с карточками»**. Он включает и
выключает всё, что связано с агентами. Выключенный, он прячет агентов из поля
исполнителя и их поля из карточек; подключённые агенты сохраняются. Что ещё
пропадает — в [«Настройках»](./index.md#ии-агенты).

Ниже — **«Агенты»**: список ваших агентов. В строке написано, что это за агент:
«Claude · программа на этом компьютере» или «Anthropic (Claude) ·
claude-opus-5-5 · Модель по ключу API». У каждого — **«Изменить»** и
**«Удалить»**.

Ещё ниже, только на компьютере, — **«Настройки прокси»**: конфигурации сети, на
которые программа-агент может ссылаться по имени.

## Подключить программу

1. **«Подключить агента…»**.
2. **«Программа на этом компьютере»**.
3. **«Программа»** — Claude, Codex, Antigravity, GitHub Copilot, JetBrains Junie
   или «ACP (other)». Для «ACP (other)» заполните **«Команда, которая запускает
   его по ACP»**, например `gemini --acp`.
4. Если программу нельзя запустить, под полем написано почему, и рядом есть
   **«Установить адаптер»** — подробнее в [«Программы-агенты: адаптеры, npx и
   Node.js»](./agents.md).
5. **«Имя»** заполнено названием программы; под этим именем агента выбирают в
   карточке. Его можно поменять до подключения.
6. **«Подключить»**.

## Подключить модель по ключу

1. **«Подключить агента…»**.
2. **«Модель по ключу API»**. На сервере выбирать не нужно: там есть только
   этот вид.
3. **«Провайдер»** — Anthropic (Claude) или OpenAI. OpenAI — это ещё и любой
   сервис с таким же API: OpenRouter, локальная модель; для них заполните
   **«Адрес (необязательно)»**, например `https://openrouter.ai/api/v1`.
4. **«Ключ API»** — вставьте ключ. Если ключ этого провайдера у вас уже есть,
   поля нет: вместо него написано **«Ключ задан»** и последние символы ключа.
5. **«Модель»** заполнена моделью по умолчанию; поле подсказывает модели,
   которые провайдер открывает вашему ключу.
6. **«Имя»** — «Claude» или «OpenAI», можно поменять.
7. **«Подключить»**. Пока ключ проверяется, на кнопке написано «Проверяю ключ…»:
   приложение спрашивает у провайдера список моделей. Если провайдер ключ не
   принял, под формой его ответ, и ни ключ, ни агент не сохраняются.

Ключ — провайдера, а не агента: на нём работают все ваши агенты этого
провайдера. Второго агента на том же провайдере ключ не спрашивает. Сменить ключ
— **«Изменить»** у любого такого агента → **«Заменить ключ»**; **«Убрать ключ»**
удаляет ключ и адрес, и агенты этого провайдера перестают запускаться, пока ключ
не появится снова.

Ключ хранится в связке ключей системы (на сервере — в файле с правами только
для приложения) и больше не показывается. Если ключ задан в окружении, в котором
запущено приложение (`PP_AI_ANTHROPIC`, `PP_AI_OPENAI`, адрес —
`PP_AI_OPENAI_URL`), в форме написано, что он меняется там.

Карточка, назначенная на модель без ключа, не запускается и пишет на себе «Нет
ключа API для …: добавьте его в «Настройки → ИИ»».

## «Ещё настройки»

У всего, что под **«Ещё настройки»**, есть рабочее значение по умолчанию, и
трогать это для первой карточки не нужно.

- **«Системный промпт агента»** — что агент слышит в начале каждой сессии,
  после промпта доски ([«Системный промпт доски»](../automation/prompt.md)).
- **«MCP-серверы»** — JSON, как его принимает любой MCP-клиент. У модели и на
  сервере — только по адресу: `{"docs": {"url": "https://…/mcp"}}`.
- У программы ещё: **«Модель (необязательно)»**, **«Путь к бинарнику»**,
  **«Команда запуска (argv)»**, **«Настройки агента»** — то, что программа
  сама о себе сообщает (например, Fast mode или effort); чтобы их узнать,
  приложение запускает программу, когда вы открываете «Ещё настройки».
  Дальше — **«Конфигурация прокси»**, **«Переменные окружения»** и
  **«Дополнительные аргументы CLI»**; у Claude — **«CLI за адаптером»** с
  Remote control.

## Что модель умеет

**На компьютере** модель работает в папке карточки, как программа: в той же
рабочей копии и на той же ветке. Она читает файлы, ищет по ним, пишет и правит
их и выполняет команды. Команда, которой нет в списке разрешённых, приходит
вопросом на карточку — «Выполнить команду: …?» — с ответами «Allow», «Allow
always» и «Refuse». Без папки на карточке модель работает в черновиках
карточки.

**На сервере** у модели нет ни файлов, ни команд: её работа — то, что она
напишет на карточке. Комментарий, значения полей, перенос в колонку, новые
карточки.

## Чьи агенты и ключи

Ваши. На компьютере — одни на установку. На сервере у каждого вошедшего свои
агенты и свои ключи: чужих агентов вы не видите ни в списке, ни в поле
исполнителя, а ваш агент работает на вашем ключе.
