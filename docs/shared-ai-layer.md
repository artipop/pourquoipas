# Общий слой ИИ для трёх проектов: сверка

Заметка, не план. Три проекта на Go и Wails с похожей логикой ИИ: XCIII
(Pourquoi Pas?), `../xxvi` (Gandvík) и `../../lead/leadheat`. Решено потом
подумать о едином слое — отдельном модуле, который все три подключают. Здесь
сверено, насколько код похож сейчас; сверено 2026-10-22.

## Требования к модулю

Сказано заранее:

- **Wails ему безразличен.** Модуль не импортирует Wails и не зависит от его
  версии: привязки, окна и шина — дело приложения.
- **SQLite — только для собственной памяти агента**, если она понадобится.
  Данных приложения модуль не видит и на них не ссылается.
- Внешние зависимости разрешены, но в трёх проектах они должны быть **одних
  версий**. Где сейчас разошлись — выровнять.

## Что похоже по устройству

- **Агент по ACP** во всех трёх: таблица адаптеров (бинарь, npm-пакет, как
  выбрать модель, что убрать из окружения), запуск в своей группе процессов,
  клиент ACP с потоком текста, разрешениями и элицитацией, имя инструмента из
  `_meta`.
- **Свой MCP-сервер, через который агент отвечает приложению**: в XCIII
  `boardmcp` (доска), в xxvi `stagemcp` («шаг готов») и `appmcp`, в leadheat
  `leadtools` и `mcpaccount`. У каждого свои инструменты, но способ один:
  выдача на прогон, сервер в процессе приложения.
- **Вопрос человеку** (разрешение или форма), который ждёт ответа и отменяется
  вместе с ходом: XCIII и xxvi.
- **Модель по ключу** (`modelapi`, `modelconv.go`) — только в XCIII.

## Кандидаты в модуль

Перечислено по тому, насколько каждый кусок не знает приложения:

1. `modelapi` — провайдеры и разговор с инструментами. Не импортирует ничего из
   XCIII.
2. `procgroup`, `userpath` — одинаковые задачи во всех трёх.
3. `secrets` — хранилище учётных данных; у xxvi своя урезанная версия.
4. Из `acp`: таблица адаптеров, разбор имени инструмента, политика, клиент ACP,
   вопросы. Сейчас они переплетены с `Manager` и `Session` XCIII; чтобы вынести,
   нужен интерфейс «куда отдать текст, кого спросить, что записать».
5. Цикл модели (`modelconv.go`): он уже говорит с доской через MCP, а не через
   код XCIII, поэтому сделать его общим можно, если инструменты папки и
   `ask_person` станут подключаемыми.
