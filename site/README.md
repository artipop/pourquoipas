# site

Сайт deffun. Статика — HTML, `styles.css`, `app.js` и шрифты; сборка нужна
только чтобы сложить их в `dist/` с хешами в именах.

```
npm ci
npm run dev        # http://localhost:5173 — сайт и все три руководства сразу
npm run dev:site   # только сайт, без руководств
npm run build      # dist/ — только сайт
npm run build:all  # dist/ вместе со всеми руководствами в dist/docs
npm run preview    # посмотреть собранное
```

Деплой — выложить `dist/` на любой статический хостинг (Pages, S3, nginx).
Адрес `/pourquoipas/` должен отдавать `pourquoipas/index.html`; у статических хостингов это
поведение по умолчанию.

**Собирать надо `build:all`.** Руководства — отдельные проекты на VitePress
(`../docs/guide` для Pourquoi Pas?, `../docs/guide-xxvi` для XXVI и
`../../six/docs/guide` для VI), но кладутся в `dist/docs`, `dist/docs/xxvi` и
`dist/docs/vi`, чтобы деплой оставался одной папкой. Порядок важен дважды:
сборка сайта чистит `dist/` перед собой, а сборка гайда Pourquoi Pas? — `dist/docs`,
внутри которого лежат остальные два. Про сам доксайт —
[`docs/guide-site.md`](../docs/guide-site.md).

**Гайд VI лежит в соседнем репозитории**, `six`, потому что документация
браузера едет вместе с браузером. Значит, для `build:all` нужно, чтобы `six` и
`pourquoipas` лежали рядом в одной папке; без этого соберётся всё, кроме него, и
`/docs/vi/` на деплое окажется пустым.

В деве каждое руководство — отдельный сервер: `../docs/guide` держит 5174,
`../docs/guide-xxvi` — 5175, `../../six/docs/guide` — 5176, а этот сервер
проксирует на них `/docs`, `/docs/xxvi` и `/docs/vi`, чтобы ссылки вели туда же,
куда поведут на деплое. Помнить про это не нужно: `npm run dev` поднимает все
четыре разом (`concurrently`, и `-k` — чтобы `Ctrl-C` уносил всех, а не оставлял
три висеть на портах). Четыре процесса здесь не архитектура, а цена VitePress: у
него свой дев-сервер, и один порт он умеет отдавать только одному сайту.
`dev:site` — когда правится сама вёрстка и руководства не нужны; тогда `/docs`
честно ответит ошибкой прокси.

## Страницы

- `index.html` — компания и список продуктов. Продукт здесь занимает одну
  карточку со ссылкой на свою страницу; у XXVI и VI своих страниц пока нет —
  оба в начале пути, и карточки ведут прямо в руководства;
- `pourquoipas/index.html` — сам лендинг Pourquoi Pas?: как работает, Входящие, терминал
  и вопросы, факты о программе, цена и форма предзаказа.

Обе страницы перечислены в `vite.config.js`: сам Vite находит только
`index.html` в корне. Шапка и футер продублированы в двух файлах — правки в
реквизитах и почте нужно вносить в обоих.

`app.js` один на две страницы: тему он помнит везде, форму находит только там,
где она есть.

## Дизайн

Токены в начале `styles.css` — те же, что в `frontend/src/styles/_tokens.scss`:
тёмная тема — экран, светлая — бумага; машина говорит разрядкой в верхнем
регистре, человек — прозой. Тему выбирает встроенный скрипт в `<head>`, до
первой отрисовки: `app.js` — модуль и выполнился бы уже после неё. Шрифты
(`fonts/`) скопированы из `frontend/node_modules/@fontsource-variable`, только
latin и cyrillic.
